Erste Schritte

Vom installierten Programm zum ersten Report in fünf Befehlen.

Installation prüfen

Windows-Warnung beim Installieren Der Installer ist noch nicht signiert. SmartScreen zeigt deshalb „Der Computer wurde durch Windows geschützt“: Weitere Informationen → Trotzdem ausführen. Adminrechte braucht die Installation nicht.

Der Installer trägt DriveLab in den Benutzer-PATH ein. In einem neuen Terminal:

Eingabeaufforderung
drivelab version
drivelab license
drivelab docs          rem öffnet dieses Handbuch

drivelab version nennt die zwei Ordner, mit denen DriveLab arbeitet:

OrdnerOrtInhalt
Installation%LOCALAPPDATA%\Programs\DriveLabProgramm, Vorlagen, SDK, dieses Handbuch, Beispiele. Wird bei jedem Update ersetzt – hier nichts ablegen.
ArbeitsordnerDokumente\DriveLabDeine Projekte (projects), deine Steuergeräte (ecus), die Lizenz. Bleibt bei Update und Deinstallation erhalten.

Beide sind im Startmenü verlinkt. Einen anderen Arbeitsordner legt die Umgebungsvariable DRIVELAB_HOME fest.

Lizenz

Ohne gültige Lizenz laufen nur version, license, help und docs. Die Datei license.lic gehört in den Arbeitsordner. Alternativ zeigt die Umgebungsvariable DRIVELAB_LICENSE auf die Datei. drivelab license zeigt den Status und, falls gefunden, welche Datei gelesen wurde.

Erstes Projekt

Eingabeaufforderung
drivelab new MeinProjekt
drivelab validate MeinProjekt
drivelab run MeinProjekt
drivelab report MeinProjekt --open
newkopiert die Vorlage nach projects\MeinProjekt
→
validatebaut alles auf, ohne zu rechnen
→
runrechnet, schreibt results\run_001
→
reportHTML-Report im Browser

Ein bloßer Name meint immer <Arbeitsordner>\projects\<Name>. Mit einem Pfad (drivelab new C:\Sim\Test) landet das Projekt woanders. Im Projektordner selbst reicht .:

Eingabeaufforderung
cd %USERPROFILE%\Documents\DriveLab\projects\MeinProjekt
drivelab run .
