Strecke, Fahrer, Sensoren

Alles, was nicht zum Fahrzeug gehört: worauf es fährt, wer es fährt und was es misst.

Strecken

Die Endung entscheidet: .xodr wird als OpenDRIVE gelesen, alles andere als DriveLab-JSON. Das JSON kennt zwei Formen:

  • Einzelstrecke – start, default_width und eine Liste segments. Schließt die Geometrie auf den Startpunkt, ist es ein Rundkurs: s läuft dann periodisch weiter.
  • Netz – {"roads": [...], "junctions": [...]} mit IDs, Verknüpfungen und Spuren. Ohne route fährt das Fahrzeug auf der ersten Straße.
JSON · Einzelstrecke
{
  "format": "drivelab-track", "version": 1,
  "start": { "x": 0.0, "y": 0.0, "hdg": 0.0 },
  "default_width": 7.0,
  "segments": [
    { "type": "line",   "length": 100.0 },
    { "type": "spiral", "length": 30.0, "curv_end": 0.02 },
    { "type": "arc",    "length": 80.0, "curvature": 0.02 }
  ]
}

arclength · curvatureKreisbogen, Krümmung > 0 = Linkskurve
spirallength · curv_end (· curv_start)Klothoide, Krümmung ändert sich linear

Je Segment darf width die Standardbreite überschreiben. Die Vorlage bringt Testfeld.json (lange Gerade, 1 km breit), einfacher_Rundkurs.json und TestLoop.xodr mit.

Route durch ein Netz

Optionaler Block route in der config.json. Drei Arten, sie anzugeben:

AngabeBedeutung
"from", "to" (, "via")Route automatisch suchen, Kreuzungen findet die Suche selbst
"roads": [...]feste Folge von Straßen-IDs; Verbindungsstraßen in Kreuzungen werden ergänzt
"start_road"ab dieser Straße den Verknüpfungen folgen
JSON · in config.json
"route": { "from": "1", "to": "7", "lane": 0 }

lane: 0 ist die innerste Fahrspur in Fahrtrichtung (Rechtsverkehr, left_hand_traffic kehrt das um). Findet die Prüfung Lücken in der Spurführung, stehen Warnungen im run.log. In Python zeigt diagnose_route die Stelle.

Fahrer

typeVerhaltenparams
"scripted"Zeitskript aus Phasen: ab t gelten die Werte, bis die nächste Phase beginntphases[ {t, gas, bremse, lenkwinkel} ]
"path"Bahnfolgeregler: hält die Mitte (Querabweichung, Kurswinkel, Krümmung vorausschauend) und passt das Tempo den Kurven ank_y · k_psi · wheelbase · v_max · a_lat_max · a_brake_plan · kp_speed · steer_max (Radlenkwinkel; mit Lenksystem rechnet der Regler selbst auf den Lenkradwinkel um, → Lenkung)
JSON · data/driver/scripted.json
{ "type": "scripted",
  "params": { "phases": [
    { "t": 0.0,   "gas": 1.0, "bremse": 0.0, "lenkwinkel": 0.0 },
    { "t": 100.0, "gas": 0.0, "bremse": 1.0, "lenkwinkel": 0.0 } ] } }

Gas und Bremse 0…1, Lenkwinkel in rad am Rad, + = links. Ein eigener Fahrer entsteht in Python, → Python.

Sensoren

Unter "sensors" stehen pov und imu. Jeder hat enabled, eine eigene Abtastrate und eine Einbaulage mount (x_m, y_m, z_m, roll_rad, pitch_rad, yaw_rad) relativ zum Fahrzeug.

SensorliefertParameter
povStreckenvorschau: Mitte und Ränder als Punkte im Sensor-Koordinatensystem, je Punkt Kurs, Krümmung, Breiterate_hz · look_ahead_m · sample_distance_m
imuBeschleunigung (ohne Erdbeschleunigung) und Drehrate im Sensorsystem, ideal ohne Rauschenrate_hz

Zwischen zwei Messungen bleibt der letzte Wert stehen; der Zeitstempel zeigt, wann er entstand. Im Lauf landen die Werte in sensors.tsv.
